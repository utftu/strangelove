# strangelove

Атомы: значение, подписки и связи между ними. На нём построена реактивность [regan](https://github.com/utftu/regan).

```bash
npm i strangelove
```

## Быстрый пример

```ts
import { createAtom, select } from "strangelove";

const price = createAtom(100);
const count = createAtom(2);

const total = select((get) => get(price) * get(count));

total.listeners.subscribe((value) => console.log(value));

count.set(3); // 300
```

## API

### `createAtom(value)`

Атом-источник: хранит значение, которое в него положили.

```ts
const source = createAtom(1);

source.get(); // 1
source.set(2); // true — значение изменилось, обновление пошло
source.set(2); // false — то же значение, обновления не будет
```

Сравнение через `===`.

### `select(cb)`

Вычисляемый атом. Зависимости не объявляются — они определяются тем, у каких атомов `cb` вызвал `get`:

```ts
const doubled = select((get) => get(source) * 2);
```

Набор зависимостей пересматривается при каждом пересчёте, поэтому условия работают как ожидается:

```ts
const out = select((get) => (get(flag) ? get(heavy) : 0));
```

Пока `flag` ложный, `out` от `heavy` не зависит и на его изменения не реагирует.

`cb` вызывается сразу при создании — у атома всегда есть значение.

### Подписки

```ts
const unsubscribe = source.listeners.subscribe((value) => console.log(value));

unsubscribe();
```

Слушатель получает новое значение атома.

### `destroyAtom(atom)`

Отцепляет атом от родителей и детей и снимает с него всех слушателей.

```ts
const derived = select((get) => get(source) * 2);

destroyAtom(derived); // source про него больше не знает
```

Нужен там, где производные атомы создаются и выбрасываются по ходу работы: на компонент, на строку списка. Без этого атом-источник держит их вечно — и в памяти, и в обходе при каждом обновлении.

Звать должен тот, кто атом создал. Уничтожать атом, полученный со стороны, нельзя: он может быть нужен ещё кому-то.

Запрета на дальнейшее использование нет: у уничтоженного атома по-прежнему можно прочитать последнее значение, а явный `update()` вычисляемому атому вернёт связи с родителями.

### `checkAtom(value)`

Проверка, что перед вами атом.

### Ручные связи

```ts
connectAtoms(parent, child); // parent -> child
disconnectAtoms(parent, child);

atom.update(); // запустить обновление от этого атома
```

Нужны редко: `select` расставляет связи сам.

## Как работает обновление

Понимание этого нужно ровно в одном месте — чтобы писать правильные `cb`.

### `cb` должен быть чистым и дешёвым

**За одно обновление `cb` может выполниться несколько раз.** Так бывает, когда `select` в ходе обновления начал читать атом, которого раньше не читал: узнать об этом можно только запустив `cb`, а прочитанное значение к тому моменту могло быть ещё не пересчитано. Тогда `cb` выполняется ещё раз, уже по актуальным данным.

Отсюда два требования:

- **никаких побочных эффектов в `cb`** — запросов, записи в хранилище, изменения внешних переменных. Всё это место подписки, а не вычисления;
- **`cb` должен быть дешёвым** — считайте, что он выполнится дважды.

Промежуточные значения наружу не выходят: слушатели срабатывают один раз, в самом конце обновления, с итоговым значением. Атом, посчитанный за обновление трижды, дёрнет слушателя один раз.

Побочный эффект в `cb` этой гарантии лишается — он выполнится столько раз, сколько выполнился `cb`. Поэтому чистота `cb` тут не пожелание, а условие, на котором держится всё остальное.

### Атом, до которого изменение не дошло, не пересчитывается

Если `cb` вернул то же значение, что было, обновление ниже по графу не идёт:

```ts
const flag = select((get) => get(source) > 0);
const heavy = select((get) => (get(flag) ? expensive() : 0));

source.set(1);
source.set(2); // flag как был true, так и остался — expensive не вызовется
```

### Циклы

Замкнутая связь — ошибка:

```ts
Atom.connect(first, second);
Atom.connect(second, first);

first.update(); // Error: strangelove: cycle in the atom graph
```

У значений в цикле нет устойчивого состояния, поэтому обновление отвергается целиком, до того как что-либо пересчитано. Цикл, сложившийся из-за условий внутри `select`, ловится так же.
